# Task overdue emphasis and progress notes — 2026-10-18

Authority: Product Owner request, ADR 0057, Slice 041 §1.6.

## Implemented behavior

Ended, unassessed Task rows show a red title and explicit Overdue text. A clock scheduled at minute
boundaries refreshes eligibility and emphasis without navigation; focus/visibility changes refresh
after suspension. Choosing an assessment removes the emphasis and undo restores it.

The existing anchored assessment rail has a fifth `+ / Note` action. Its accessible multiline
editor saves one optional progress note, renders it immediately below the corresponding Task, and
retains input after an error. Reopening edits the saved value; saving blank text clears it.
Keyboard navigation, Escape, focus restoration, and a modal focus trap are exercised. Note writes
do not change assessment, Analytics source revision, the original Description, or other occurrences.

Schema 34 is append-only. The new table uses Task/series foreign keys and unique subject indexes.
Rust validates subject identity, existence, scheduled end and text bounds before transactional
upsert/delete. Moved recurring occurrences retain their original-date identity. Startup, backup
inventory, backup validation and restore all use the new current schema. DTOs and the narrow Tauri
permission are generated by the existing Rust/Tauri tooling.
