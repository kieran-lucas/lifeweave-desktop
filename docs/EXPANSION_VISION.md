# Expansion Vision

Status: **Retained vision, not implementation authorization.**

This document preserves high-value long-term ideas from the original specification while preventing them from constraining Core before evidence exists.

## Activation rule

An expansion item may enter implementation only when:

1. a real dogfooding problem demonstrates need;
2. the Product Owner promotes it through a decision/ADR;
3. a feature spec defines behavior, out-of-scope, migration and acceptance;
4. dependency and bundle impact are reviewed;
5. a prototype gate is passed where required;
6. Core data safety and performance are not weakened.

## 1. Completion prediction

Potentially rank/emphasize radial choices using local history and contextual features. Constraints remain fixed:

- entirely local;
- stable logical option order;
- bounded visual emphasis;
- low-probability choices remain equally operable;
- cold-start fallback;
- failure never blocks manual choice;
- opt-out and calibration evidence.

Start with a transparent heuristic. Do not introduce a machine-learning framework until measured benefit exceeds complexity.

## 2. Global scoring

A versioned 0–100 score may combine evaluation, priority, category, duration, goals, missed state, and period context.

Before activation, define:
- anti-farming properties;
- caps and monotonicity;
- fixed-point/rounding policy;
- historical recompute versus snapshot preservation;
- sensitivity analysis;
- understandable component statistics;
- golden fixtures and property tests.

Do not let score become the only interpretation of personal performance.

## 3. Anime Narrative Canvas

Long-term leaf documents may become a constrained scene/block composition system with:

- static Reader and active Studio;
- versioned canonical document;
- scene presets;
- typed block registry;
- template-first authoring;
- structured data blocks;
- portable Markdown fallback and lossless canonical export;
- bounded motion and theme atmosphere.

This is a product platform, not a small editor feature. It requires a dedicated prototype and migration strategy.

### Retained visual direction

**Abstract Anime Editorial**, using light, sky, crystal, orbit, stars, abstract petals, geometry, layered space, editorial typography, and title-sequence-like motion.

Explicitly excluded:
- copyrighted anime characters or fanart;
- gacha framing;
- default visual novel dialogue;
- dense cyberpunk neon;
- video backgrounds;
- unrestricted pixel canvas.

## 4. Visual worlds

Branch-level theme worlds may include Celestial Nexus, Azure Observatory, Midnight Research Grid, Amber Vault, Verdant Pulse, Rose Nebula, and later bounded additions.

Activation requires:
- complete semantic token contract;
- light/dark contrast fixtures;
- asset budget;
- idle CPU/GPU measurement;
- Reduced Motion behavior;
- inheritance and migration policy.

## 5. Knowledge features

The following retain substrate ideas but remain individually OPEN/DEFERRED:

- Search beyond basic needs.
- Tags.
- Backlinks.
- Outline.
- Noteboard.
- Graph.
- Saved views/filter AST.

None may be bundled together as a “knowledge suite” without separate use cases. Graph never replaces the Life tree.

## 6. Distribution expansion

Public code signing, WinGet, updater, SBOM, and polished public release automation activate only when internal Core builds are stable and distribution is intended.

## 7. Rejection criteria

Reject or postpone an expansion when it:
- duplicates a simpler existing flow;
- adds permanent schema for speculative UI;
- weakens offline guarantees;
- obscures Task-first navigation;
- creates editor/framework lock-in;
- increases idle resource use without daily value;
- requires the user to maintain a system instead of using it.
